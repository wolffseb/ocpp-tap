You address review comments on one pull request of the `wolffseb/ocpp-tap` Go repo (`octap`, a self-hosted OCPP 1.6-J proxy: a minimal forwarder in the charging path plus a read-only tap). You run in your own git worktree; work only there.

GitHub: in a cloud session use the GitHub MCP tools (`mcp__github__*`, owner `wolffseb`, repo `ocpp-tap`); there is no authenticated `gh` there. On a workstation, `gh ... -R wolffseb/ocpp-tap` works too.

At the end, add any new **durable, non-obvious** lesson, for example a test pattern that worked, a trap in this codebase, or a fix that a reviewer rejected and why. ## Process

1. Collect the comments: the PR's review threads (inline) and its reviews (bodies). Ignore comments that already have a reply saying they were handled.
2. Get onto the right branch:
   - open PR: `git fetch origin <headRefName> && git checkout -B <headRefName> origin/<headRefName>`
   - merged PR (you will be told): branch off `origin/main` with the name you are given, and open a new PR against `main` at the end.
3. For each comment, first decide if it is correct by reading the code. If it is wrong or not worth doing, do not change code; say why in the reply.
4. For each valid comment: write the test it asks for first and see it fail (or show the race with `-race`), then fix, then see it pass. Match the surrounding code: naming, comment density, error style, the harness helpers (`harness/cpms`, `harness/recorder`, `harness/loadgen`, `harness/frames`, e2e `newRig`).
5. Never fix by weakening: no relaxed acceptance test, target, timeout or frame-identity check, and no change to the forwarder's principles (`CLAUDE.md`). If a comment can only be satisfied that way, decline it and say why.
6. Before every commit: `gofmt -l .` is empty, `go vet ./...` and `go test -race ./...` pass; before pushing, `make ci` and, if anything under `internal/forwarder`, `cmd/octap`, `harness` or `e2e` changed, `make e2e`. If a test is flaky, fix the cause, don't retry until green.
7. One commit per comment, imperative subject line in the repo's style (see `git log --oneline -20`), ending with:
   `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`
8. `git push origin <branch>` (never force-push, never push to `main`, never merge).
9. Reply to each inline comment with "Fixed in <short sha>: <one line>" or the reason it was not changed, and resolve the threads you fixed. For a merged PR, link the new follow-up PR instead. Every reply ends with a blank line, `---`, and `_Generated by [Claude Code](https://claude.ai/code)_`.
   A new PR's description ends with: `🤖 Generated with [Claude Code](https://claude.com/claude-code)`
10. **Re-assess the merge-risk light** by `docs/merge-risk.md` from the new diff. If it changed, swap the `merge-risk: *` label and say why in a PR comment. You never merge, whatever the light.

## Report back

Per comment: fixed (sha) / declined (why). Plus the branch, the final `go test -race ./...` result, CI on the new head, the merge-risk light after your pass, and the PR URL if you opened one.
